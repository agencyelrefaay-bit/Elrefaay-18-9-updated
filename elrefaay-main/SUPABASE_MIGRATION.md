# الانتقال من SQLite إلى PostgreSQL (Supabase) — دليل التشغيل

هذا الدليل يشرح خطوة بخطوة كل حاجة محتاج تعملها عشان تشغّل النظام على قاعدة
بيانات PostgreSQL حقيقية عبر Supabase، بدل sql.js (SQLite في الذاكرة).

## ما الذي تغيّر في الكود؟

- تم استبدال طبقة قاعدة البيانات بالكامل (`src/db/database.js`) لتعمل مع
  PostgreSQL عبر مكتبة `pg` بدل sql.js.
- كل توابع قاعدة البيانات (`run`, `get`, `all`, `insert`, `transaction`)
  أصبحت **غير متزامنة (async)** — وبالتالي كل نقطة في الكود كانت بتستدعيها
  اتضاف لها `await`. هذا التغيير طال 23 ملف route وكل ملفات `utils/` المرتبطة
  بقاعدة البيانات.
- نصوص استعلامات SQL نفسها **لم تتغيّر تقريباً** — تمت إضافة طبقة ترجمة
  شفافة (shim) داخل `database.js` تتولى تحويل أي دالة خاصة بـ SQLite
  (`datetime('now')`, `strftime()`, `INSERT OR IGNORE`, علامات `?`) لصيغة
  PostgreSQL تلقائياً عند التنفيذ، فتقليل فرصة الأخطاء عند التعديل اليدوي.
- تم تحديث `schema.js` بالكامل: `AUTOINCREMENT` → `SERIAL`, `REAL` →
  `DOUBLE PRECISION` (لدقة مالية أعلى)، وإصلاح استعلامات `GROUP BY`/`HAVING`
  التي كانت تعمل في SQLite (أكثر تساهلاً) لكنها ممنوعة في PostgreSQL
  (أكثر صرامة في التحقق من صحة الاستعلام).
- تمت إضافة `express-async-errors` عشان أي خطأ غير متوقع في أي route
  (async) يوصل تلقائياً لمعالج الأخطاء العام، بدل ما "يعلّق" الطلب من غير
  رد على المستخدم.
- ملف قاعدة البيانات القديم (sql.js) موجود كنسخة احتياطية للمرجعية فقط في
  `src/db/database.sqlite.bak.js` (غير مستخدم في التشغيل الفعلي أبداً).

**تم اختبار كل هذا التحويل فعلياً** (وليس نظرياً) ضد سيرفر PostgreSQL حقيقي
محلي يحاكي Supabase، شاملاً: تسجيل الدخول، الفواتير والخصومات، المدفوعات
ومنع تجاوز السداد، أوامر الشراء والاستلام (بما فيها حساب متوسط التكلفة
المرجّح عبر المخازن)، العمولات التلقائية، كل التقارير، والتحويلات المخزنية
— بالإضافة لنقل بياناتك الحقيقية الفعلية (٢٦٩ صف عبر ٣٠ جدول) والتأكد من
ظهورها صحيحة ١٠٠٪ عبر الواجهة.

---

## الخطوة ١: إنشاء مشروع Supabase

1. سجّل / سجّل دخول على [supabase.com](https://supabase.com)
2. أنشئ **New Project**، واختر:
   - اسم المشروع (مثال: `najaf-erp`)
   - **كلمة مرور قاعدة البيانات** — احفظها في مكان آمن، هتحتاجها في الخطوة القادمة
   - المنطقة (Region) — اختر الأقرب جغرافياً لسيرفرك (مثلاً `eu-central-1` أو أقرب منطقة لمصر)
3. انتظر دقيقتين لحد ما المشروع يتجهز.

## الخطوة ٢: الحصول على رابط الاتصال (Connection String)

1. من لوحة تحكم Supabase: **Project Settings** (⚙️) → **Database**
2. تحت **Connection string**، اختر تبويب **URI**
3. **مهم جداً بخصوص نوع الاتصال (Pooler mode):**
   - Supabase بيوفّر ٣ طرق اتصال: **Direct connection**، **Session pooler**،
     و **Transaction pooler**.
   - استخدم **Session pooler** (المنفذ عادة `5432` على host بيبدأ بـ
     `aws-0-...pooler.supabase.com`) — ده الأنسب لسيرفر Node.js تقليدي زي
     مشروعنا (مش بيئة serverless). الاتصال المباشر (Direct) يعمل برضه لكنه
     محدود العدد وممكن ما يدعمش IPv4 على كل الشبكات، والـ Transaction pooler
     ممكن يسبب مشاكل مع بعض عمليات SQL المتقدمة.
4. انسخ الرابط، واستبدل `[YOUR-PASSWORD]` بكلمة مرور قاعدة البيانات من
   الخطوة ١.

## الخطوة ٣: إعداد متغيرات البيئة

1. انسخ ملف `.env.example` الموجود في المشروع وسمّه `.env`
2. الصق رابط الاتصال في `DATABASE_URL`
3. تأكد إن `DATABASE_SSL=true` (مطلوب دائماً مع Supabase)
4. غيّر `JWT_SECRET` لقيمة عشوائية طويلة وسرية (استخدم أي أداة توليد كلمات
   مرور، أو نفّذ هذا الأمر وانسخ الناتج: `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`)

## الخطوة ٤: تثبيت الحزم المطلوبة

```bash
npm install
```

هذا هيثبّت `pg` (عميل PostgreSQL) و `express-async-errors` اللي أضفناهم،
وهيشيل `sql.js` القديم غير المستخدم بعد كده.

## الخطوة ٥: إنشاء الجداول في القاعدة الجديدة

شغّل السيرفر مرة واحدة فقط عشان ينشئ كل الجداول تلقائياً (نفس آلية إنشاء
الجداول كانت موجودة قبل كده، فقط الآن بتتنفذ على PostgreSQL):

```bash
node server.js
```

هتلاقي رسائل تأكيد زي:
```
✓ تم الاتصال بقاعدة بيانات PostgreSQL بنجاح (postgres)
✓ تم إنشاء/تحديث مخطط قاعدة البيانات بنجاح
...
✓ السيرفر يعمل على المنفذ 5000
```

بعد التأكد إن الرسائل ظهرت صح، أوقف السيرفر (Ctrl+C). دلوقتي عندك قاعدة
PostgreSQL فيها كل الجداول فارغة (+ بيانات افتراضية بسيطة زي مستخدم admin
تجريبي ومواقع افتراضية — هنستبدلها ببياناتك الحقيقية في الخطوة الجاية).

## الخطوة ٦: نقل بياناتك الحقيقية من الملف القديم

عندك ملف `data/erp.sqlite` فيه كل بياناتك الحالية (المنتجات، الفواتير،
العملاء... إلخ). سكريبت `migrate-data.js` هينقلها بالكامل لقاعدة PostgreSQL
الجديدة، بنفس الأرقام التسلسلية (IDs) بالضبط، وبيمسح أولاً أي بيانات
افتراضية اتنشأت في الخطوة ٥ عشان محصلش تضارب.

```bash
npm install sql.js --no-save   # مطلوب مؤقتاً فقط لقراءة الملف القديم
node migrate-data.js --confirm
```

هتشوف تقرير مفصّل بعدد الصفوف المنقولة من كل جدول. في الآخر هيطبع:
```
✓ اكتمل النقل بنجاح — إجمالي XXX صف عبر ٣٠ جدول
```

بعد التأكد إن النقل نجح، ممكن تشيل `sql.js` تاني لو حابب (مش هتحتاجها في
التشغيل العادي بعد كده):
```bash
npm uninstall sql.js
```

## الخطوة ٧: التشغيل والتحقق

```bash
npm start
```

افتح النظام وتأكد إن:
- تسجيل الدخول بنفس بيانات المستخدمين القدام شغال
- الفواتير والعملاء والمنتجات القديمة كلها ظاهرة
- تقدر تعمل فاتورة جديدة وتؤكدها بنجاح

## ملاحظات مهمة

### الأداء والاتصالات (Connection Pooling)
الكود بيستخدم `pg.Pool` بحد أقصى ١٠ اتصالات متزامنة افتراضياً (`DATABASE_POOL_SIZE`
في `.env`). خطة Supabase المجانية بتدعم حتى ٦٠ اتصال مباشر أو أكتر بكتير عبر
الـ pooler — الإعداد الحالي آمن لحجم استخدام مؤسسة متوسطة. لو لاحظت بطء تحت
ضغط استخدام عالي جداً، ممكن نرفع الرقم ده.

### النسخ الاحتياطي
- ملف `data/erp.sqlite` القديم **لم يُحذف ولن يُعدَّل أبداً** بأي من هذه
  الخطوات — احتفظ بنسخة منه في مكان آمن كنسخة احتياطية تاريخية حتى بعد
  اكتمال النقل بنجاح.
- Supabase بيعمل نسخ احتياطي تلقائي يومي لقاعدة البيانات (حسب الخطة).
  راجع **Database → Backups** في لوحة التحكم للتأكد من التفعيل.

### الأمان
- **لا تشارك `DATABASE_URL` أو `JWT_SECRET` مع أي حد**، ولا ترفعهم على
  GitHub أو أي مكان عام. ملف `.env` لازم يفضل بره أي نظام تحكم بالإصدارات
  (تأكد وجود `.env` في `.gitignore`).
- كلمة مرور قاعدة البيانات ممكن تتغيّر لاحقاً من **Project Settings → Database**
  في Supabase لو حسيت إنها اتسربت.

### لو حصلت مشكلة
- تأكد إن `DATABASE_URL` منسوخ صح بالكامل (خصوصاً كلمة المرور — لو فيها
  رموز خاصة زي `@` أو `#`، لازم تُرمَّز URL-encoded).
- تأكد إن IP الخاص بالسيرفر مش محظور في **Database → Network Restrictions**
  في Supabase (افتراضياً مفتوح للجميع، لكن ممكن يكون مقيّد حسب إعداداتك).
- سجل الأخطاء الكامل بيظهر في الـ console عند تشغيل `node server.js` —
  ابعتلي رسالة الخطأ الكاملة لو احتجت مساعدة إضافية.
